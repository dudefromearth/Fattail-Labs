# Flagged Ideas Register

One mechanism of **doctrine principle 10 — the bench strengthens with every
invocation**. Flags keep valuable intent available to future sessions; they are not
process theater.

Append-oriented. Ideas are flagged, discussed, and disposed by Coach
(ADOPTED / DEFERRED / PARKED / RESHAPED) — never silently erased.

**Process:** `agents/bench/spec-create-review-workflow.md` (Bench delta & idea flags)  
**Owners:** Reviewers open flags · Juliet/Lima update status · Coach disposes

| Status | Meaning |
|--------|---------|
| `OPEN` | Needs discussion |
| `DISCUSSED` | Talked through; disposition pending write-up |
| `ADOPTED` | In build-authority scope (cite spec version) |
| `DEFERRED` | Later phase/version (cite when) |
| `PARKED` | Valuable; no schedule; revisit trigger noted |
| `RESHAPED` | Intent kept; form changed (cite new wording) |

Do **not** use `DISCARDED` / `REJECTED` as idea status.

## How to add a flag

1. Allocate next `FI-NNN`.  
2. One-line idea + source doc + who flagged + why (cite invariant/spec if any).  
3. Status `OPEN`.  
4. Juliet schedules discussion; Coach disposes; update Status + Disposition note same day.  
5. Material batches may also get a decision-log entry; the register remains the index.
