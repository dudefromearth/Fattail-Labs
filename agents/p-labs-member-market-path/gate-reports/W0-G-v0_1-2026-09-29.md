## Wording error (not a FAIL)

Spec §1 row 2 says the session-status last document is served "with `stale`". Spec §2 "Stale over wait" says the last value is served "with the existing `stale` field true". Spec §2 "Browser JSON unchanged" says "no new key on any route" and that `stale` and `epoch_quality` are already on the wire where they exist.

`GET /api/me/market/session-status` has no `stale` key. Putting one on the response would be a new JSON key. Q3, DL-805, rules that the no-new-key sentence governs. Today's keys stay. A served-last session document is signalled by nothing new. Universe staleness already uses `mark_stale`, not a field named `stale`.

That conflict is a spec wording error. It is corrected in spec v0.2 when the next version is cut for any other reason. This gate does not cut spec v0.2 and does not edit spec v0.1. It is not a FAIL.
