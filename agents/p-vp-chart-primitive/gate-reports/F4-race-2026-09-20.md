# F4 race — diagnostic (before REQ-007 phase A)

**Date:** 2026-09-20  
**Machine:** StudioTwo (read of `SaPriceChart.tsx` as-shipped before phase A)  
**Ruling:** F4 fix is **replacement**, not repair. This artifact names where the race lives.

## Trace (effect order, same component)

React runs `useEffect` in source order:

1. Chart create `[]` — `createChart`, `attachPrimitive` (`SaPriceChart.tsx` ~L142–181). Primitive is attached **before** data.
2. OHLC load (`[source, priceTf, …]`) — async `fetchGenWait` then `setData` + `setVisibleRange` (~L183–271).
3. VP band `ensure()` (`[source, spanFloor, profileMode, …]`) — **calls `ensure()` immediately** (~L607) and also `subscribeVisibleTimeRangeChange`.

On a **fresh authed load**, (3) runs while (2) is still in flight. `timeScale().getVisibleRange()` is empty.

## Deleted-path branch (the race)

```533:551:web/components/sa/SaPriceChart.tsx
      const vis = chartRef.current?.timeScale().getVisibleRange();
      const fromT = vis && typeof vis.from === "number" ? Number(vis.from) * 1000 : 0;
      const toT = vis && typeof vis.to === "number" ? Number(vis.to) * 1000 : 0;
      const url = vr && fromT && toT
        ? windowUrl(...)
        : rangeUrl(...);   // first load → FULL HISTORY /range
```

When `vr` is true but `fromT`/`toT` are 0, the client does **not** wait. It fetches `/range` (old first-load choreography). `beginBandFetch` marks inflight; a later visible-range event only sets `pending`. The first paint of the profile is the stale `/range` result (or empty if `spanFloor` is still null). **Zero-interaction draw fails.** A pan unblocks it. That is F4.

A second `/range` retry when window bins are empty (~L586–599) is the same path.

## Surviving attach/lifecycle?

Primitive `attached()` runs in effect (1), before OHLC. `_requestUpdate` is wired. That order **survives** and is correct.

`priceToCoordinate` is null until the series has data **and** LWC has painted. That is a scale-ready constraint, not a missing `attachPrimitive`. Phase A must:

- kick the **window** fetch from the OHLC `apply()` after `setData` + `setVisibleRange`, using the **intended** `defaultTimeWindow` timestamps (do not wait on `getVisibleRange()`);
- `requestUpdate` + one `requestAnimationFrame` after bins land so the first LWC paint has coordinates.

No separate attach-order bug to patch on the old overlay/`/range` path.

## Verdict

| Question | Answer |
|----------|--------|
| Race in the deleted first-load `/range` fallback? | **Yes.** |
| Race in primitive attach ordering that survives? | **No.** Attach is already before data. Scale-ready after `setData` is handled inside the new window kick. |

Phase A deletes the fallback and the retry. It does not ship a repair on `/range` first-load.
