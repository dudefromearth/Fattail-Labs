# REQ-006 v2 — Lookback is a fixed bar count per interval

**Status:** OPEN. Supersedes v1 (calendar 90-day window).  
**Captured:** 2026-09-19.

**Coach wording (RL-1):**

> There should be a fixed number of intervals or candles we can go back, so it will be different for the different time chart intervals.

## The law

1. Default served depth for futures chart kinds is **N BARS** at the chart's interval — not a calendar window. The provider converts bars → date range server-side using the symbol's session calendar via `metadata_ref` (first live consumer of the VP-L3 join). The 90d calendar-window model is **DELETED** (grep-proof). One model: N bars, pan pages, cap at birth.
2. N is a versioned provider/surface parameter, per interval class. Seated starting values, Coach overrides: **5000 bars** initial serve, **5000-bar pages** on pan-toward-left-edge (SRF-4 viewport paging).
3. Cap at contract birth: when N bars exceed the contract's life, the serve reaches first-traded-bar and is **COMPLETE** — no banner. SHORT HISTORY fires only when the serve is shorter than the rule **AND** the contract holds more. MASSIVE EMPTY stays its own named state.
4. Payload adds: `bars_served`, `bars_rule`, `at_contract_birth` bool, alongside existing span/short_history fields.
5. LOD budget (SRF-4) proven at full N on both roots — pan performance attested, not assumed.

## Sequencing
