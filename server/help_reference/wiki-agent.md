# Wiki agent — administrators only

This topic is for **site administrators**. Members and signed-out visitors never
see a Wiki agent button. If you are a member looking for the knowledge map, use
**Apps → IKI Lab → Wiki** (`/app/wiki`) and search — that is the Wiki, not the
Wiki agent. The Wiki agent writes drafts; it does not publish, and it never
makes profit claims.

## Who sees the Wiki agent
Only accounts with the administrator role. The control is a zinc pill labelled
**Wiki agent** (sentence case), lower right of the page, immediately **left of**
the emerald **Help** pill. On `/admin` pages Help is hidden; Wiki agent stays,
still lower right. Members: the button is not in the page at all.

## Where it appears
On the **entire Labs plane** — Apps, Wiki, Options Lab, Trade Log, courses,
admin, and other AppChrome screens — not only inside IKI Lab. One button. There
is no second orb on Wiki routes.

## What it is for
Standing presence while you work: capture a finished page, or run a short
session whose context is the screen you are on. Everything in the window is a
proposal until you send a draft to the board. **You still approve.** Nothing
files itself. Nothing publishes itself.

## Open the window
Click **Wiki agent**. The panel stays in the lower right. Close with **×**; the
pill comes back. The window fills **Surface** and **Route** from the page you
are on (for example Options Lab Heatmap → surface `options-lab`, route
`/app/options-lab/heatmap`). You can edit those fields if they are wrong.
Unregistered screens still work — route only, less detail.

## Hand off a finished page
Use **Hand off** when the material is already **finished and publishable**.
Paste the page body and one line of intent (what this is for). This is a
delivery point — the window does not hold a draft queue. Thin copy or copy that
makes a profit claim will not become a page. You will see a named reason, not a
silent miss.

## Open a session
**Open session** starts a multi-turn conversation. The first agent turn should
cite the calling context (surface, route, and entity if known), then wait.
Type what the page should cover and **Send**. Proposals stay in the window.
They do not write git and they do not touch the board until you choose
**Draft to board**.

## Draft to board
**Draft to board** writes a git draft (`status: draft`) and a board card
**awaiting_approval**. The window says “Draft on the board — you still
approve.” It never says Published. You (or another admin) publish from the
board / git. Members see the page after the wiki host pulls and reindexes.

## Seal a session
**Seal session** freezes the transcript. You cannot add turns after seal.
Follow-on work is a **new** session. Do not expect the window to seal itself
when you change routes.

## Drain queued revisions
**Drain queued revisions** pulls the next items from the linkage queue onto
the board. You still approve each card. This is housekeeping for suggested
link updates, not a publish button.

## What the Wiki agent will not do
It will not publish. It will not invent a profit story. It will not appear for
members. It will not clone Help’s emerald button. It will not replace the
member Wiki: readers still use search, Start here, articles, and the graph.

## If you are a member
You do not have this tool. Read the Wiki (`/app/wiki`). Ask product questions
with the emerald **Help** button. If a page is missing, that is a content gap
for the teaching map — not something Help can publish for you.
